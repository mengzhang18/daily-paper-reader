## 摘要
大型语言模型（LLMs）通过实现无需任务特定微调的数据库自然语言接口，推进了文本到SQL（Text-to-SQL）技术。然而，现有的基于LLM的系统仍不可靠，经常生成在数据库模式（schema）下无效的SQL查询，引用不存在的表、属性、函数或值。此类错误持续存在，因为与数据库管理系统（DBMS）的交互通常仅限于错误消息，这使得DBMS在查询精化过程中扮演的角色在很大程度上是被动的。本文提出SafeQL，一种基于搜索的精化范式，重新定义了DBMS在精化过程中作为积极引导者的角色。SafeQL不在执行失败后重新生成整个查询，而是解释DBMS反馈，仅增量修复出错的组件。每个精化步骤被表述为在安全查询空间（safe query space）内的引导搜索，其中候选查询通过DBMS执行逐步验证，从而收敛到可执行查询，并防止错误的重复生成。在Bird和Spider基准上的实验表明，与基于重新生成的方法相比，SafeQL显著提高了执行准确性和效率。

## Abstract
Large language models (LLMs) have advanced Text-to-SQL by enabling natural language interfaces to databases without task-specific fine-tuning. However, existing LLM-based systems remain unreliable, often generating SQL queries that are invalid under the database schema, referencing non-existent tables, attributes, functions, or values. Such errors persist because interactions with the database management system (DBMS) are typically limited to error messages, leaving it in a largely passive role during query refinement. This paper proposes SafeQL, \textit{a search-based refinement paradigm that redefines the role of the DBMS as an active guide in the refinement process}. Instead of regenerating entire queries after execution failure, SafeQL interprets DBMS feedback to incrementally repair only the erroneous components. Each refinement step is formulated as a guided search within a \textit{safe query space}, where candidate queries are progressively validated through DBMS execution, thereby converging to an executable query and preventing repeated regeneration of errors. Experiments on the Bird and Spider benchmarks show that SafeQL significantly improves execution accuracy and efficiency compared to regeneration-based methods.

### 1. 核心问题与整体含义（研究动机与背景）
- **背景**：Text-to-SQL 是自然语言接口数据库（NLIDB）的核心任务，旨在将自然语言问题转换为可执行的 SQL 查询。LLM 的出现使得无需任务特定微调即可生成 SQL，但生成结果仍普遍不可靠，常出现引用不存在的表、列、函数或值等模式级错误。
- **核心问题**：现有基于 LLM 的 Text-to-SQL 系统大多采用“重新生成（regeneration）”范式：执行 SQL → 获取 DBMS 错误信息 → 提示 LLM 重新生成完整查询。该范式存在两大缺陷：
  - **效率低**：每次失败都丢弃整个查询并重新生成，产生大量 token 消耗和计算延迟，且重复执行大量已正确的片段。
  - **不可靠**：错误信息通常缺乏可操作的语义线索，重新生成往往导致错误反复出现，且无法保证收敛。
- **整体含义**：论文提出重新定义 DBMS 在精化过程中的角色——从“被动错误报告者”转变为“主动引导者”，通过**搜索式精化（search-based refinement）** 取代反复重新生成的循环，从而提升 LLM Text-to-SQL 系统的安全性和效率。

### 2. 方法论：核心思想、关键技术细节、算法流程
- **核心思想**：当生成的 SQL 执行失败时，不丢弃原查询，而是分析 DBMS 反馈，精确定位错误组件（关系、属性、函数等），通过**结构保持的最小修复**逐步将查询转换为可执行形态。精化过程被建模为在**安全查询空间（safe query space）** 内的引导搜索，每个候选都通过 DBMS 执行验证，保证收敛。
- **关键概念与定义**：
  - **精化步（Refinement Step）**：五种原子操作——关系精化、连接精化、属性精化、值精化、函数精化。每种操作只修改一个语法组件。
  - **安全精化树（Safe Refinement Tree）**：以失败查询为根，根据错误类型（未知关系、未知属性、未知函数、空结果）仅展开可接受的精化操作，形成一颗树；其叶子节点构成安全查询空间 Q_safe。
  - **可达性引理（Lemma 7）**：对每个执行错误类型，都存在一种可接受精化操作恢复被违反的执行前提，从而保证安全精化树中至少存在一条通向可执行查询的路径。
  - **语义距离（Semantic Distance）**：由结构树编辑距离（AST 层面）和嵌入向量距离（替换 token 的 embedding 差异）加权组合，用于衡量候选查询与原查询的语义偏差。
- **搜索算法（Best-first Search）**：
  - 以原查询为根，使用按语义距离排序的优先队列。
  - 每次取出距离最近的候选执行；若成功则返回（第一个成功者即语义最近的安全查询）；若失败则按错误类型生成可选精化，经过剪枝后加入队列，并避免重复访问。
- **剪枝优化**：
  - **类型剪枝**：利用数据库类型系统（Γ），丢弃类型不匹配的精化候选。
  - **Top-K 剪枝**：对每一类候选（关系、属性、值、函数）按嵌入相似度排名，仅保留前 K 个最相关的，减少搜索分支数。
- **系统级设计**：
  - **DBMS 内集成**：在 PostgreSQL 的 AST（RawStmt）上直接定位错误节点，避免文本解析歧义。
  - **缓存与向量索引**：预计算并缓存关系/属性/值的 embedding，使用 HNSW 向量索引加速 Top-K 最近邻查找。
  - **混合精化策略**：当搜索步数达到阈值（默认 100）仍无法得到有效查询时，触发 LLM 重新生成，处理初始查询严重错位的场景。
  - **语法扩展**：支持嵌套子查询（由内向外递归精化）、别名、GROUP BY / ORDER BY / LIMIT 等 SQL 子句。
