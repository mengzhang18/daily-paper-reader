## 摘要
在语义数据处理系统中，一次LLM调用的成本足以主导查询成本，但其延迟又足以将CPU端学习器的更新隐藏在其往返时间之后。在生产环境中，LLM计算占查询成本的80-90%，每次调用的成本是关系谓词的10^5-10^7倍。延迟窗口颠覆了经典自适应查询处理的设计约束——在经典方法中，在线学习器必须保持轻量，以避免主导其所优化的谓词。在LLM延迟级别，每次调用的梯度步长和每批次的阈值求解都能在往返时间内完成。我们在LLM调用边界上开发了组合式在线学习：一个用于在语义数据处理系统中组合在线学习组件的框架。每个组件在执行时做出决策，并在线优化其学习产物。设计空间跨越两个轴：决策粒度和学习器更新节奏，组件共享一种单一的学习模式，将每个训练器步骤隐藏在下一次LLM往返过程中。一个生产案例研究（Cortex AISQL）组合了三个组件：记忆化层、在线每调用过滤排序学习器和在线每批次级联路由学习器。条件成本分解将每个学习组件分配给每行LLM成本的不同因子。在独立性假设下，两个学习组件组合相乘，对代表性合取过滤工作负载产生11.4倍的上界。级联边界的自选择、样本预算缩减和选择性估计漂移将其降低到接近8倍的实际数值。

## Abstract
An LLM call in a semantic data processing system is expensive enough to dominate query cost, yet slow enough to hide a CPU-side learner's update behind its round-trip. In production, LLM compute accounts for $80-90\%$ of query cost, and each call costs $10^5-10^7\times$ a relational predicate. The latency window inverts a design constraint of classical adaptive query processing, where online learners had to stay lightweight to avoid dominating the predicates they optimize. At LLM latency, per-call gradient steps and per-batch threshold solves fit inside the round-trip. We develop compositional online learning at the LLM call boundary: a framework for combining online-learning components in semantic data processing systems. Each component makes execution-time decisions and refines its learned artifacts online. The design space spans two axes, decision granularity and learner update cadence, and the components share a single learning pattern that hides each trainer step inside the next LLM round-trip. A production case study in Cortex AISQL composes three components: a memoization layer, an online per-call filter-ordering learner, and an online per-batch cascade-routing learner. A conditional cost decomposition assigns each learning component to a distinct factor of per-row LLM cost. Under independence, the two learning components compose multiplicatively to an $11.4\times$ upper bound on a representative conjunction-filter workload. Self-selection at the cascade boundary, sample-budget shrinkage, and selectivity-estimation drift reduce it to a realistic figure near $8\times$.

## 1. 核心问题与整体含义（研究动机与背景）

- **成本与延迟的不对称性**：在语义数据处理系统中，每行数据上的 LLM 调用成本极高（生产中占查询总成本的 80–90%），单次调用开销是关系谓词的 \(10^5\sim10^7\) 倍；同时单次 LLM 往返延迟达数百毫秒至秒级，足够在后台完成一次 CPU 端的学习器更新。
- **经典自适应查询处理（AQP）的局限**：传统 AQP 假设谓词在纳秒/微秒级执行，在线学习器必须保持极轻量，否则会主导被优化的谓词开销。LLM 延迟窗口使这一约束反转：在线学习可以“隐藏”在 LLM 往返时间内，不再需要牺牲学习器复杂度。
- **核心问题**：多个在线学习组件如何在 LLM 调用边界上组合？它们的收益是否能叠加？该问题在已有文献中基本未被研究。
- **整体意义**：本文提出“LLM 调用边界的组合式在线学习”框架，为语义数据系统（如 Cortex AISQL）的执行期优化提供新范式，并首次尝试建立组合理论，展示多个在线学习组件如何协同作用。

## 2. 方法论

### 2.1 核心思想
- **LLM 延迟窗口反转设计约束**：将 CPU 侧训练步骤隐藏在一次 LLM 往返中，形成流水线模式：预测 → 发起 LLM 调用 → 后台训练 → 记录结果。
- **共享学习模式**（图 1）：
  1. 优化器查询当前学习产物，决定下一步决策，同时派发后台训练步骤；
  2. 将决策发送给 LLM，训练在往返期间完成并按回写产物；
  3. LLM 结果进入监督缓冲，供下一次训练使用。
- **设计空间**：以“决策粒度”（per-call / per-row / per-batch）和“学习器更新节奏”（online per-call / online per-batch / one-shot / offline / none）为两轴，构成层次化设计空间（表 1）。AISQL 实例占据三个单元格：
  - 响应缓存（记忆化，无学习器）；
  - 过滤排序（Larch，online per-call）；
  - 级联路由（GAMCAL，online per-batch）。

### 2.2 关键技术细节

#### 过滤排序（Larch）
- 目标：减少每行期望谓词求值次数 \(\bar e\)，利用短路求值。
- Larch-Sel 方法：
  - **选择性估计器**：两层 MLP（约 144K 参数），输入为文档/谓词嵌入投影拼接特征 \([d \parallel f \parallel d \odot f \parallel \cos(d,f)]\)，输出 sigmoid 预测通过概率，采用二分类交叉熵（BCE）训练；所有谓词共享权重，可从第一次求值起迁移学习。
  - **DP 排序求解器**：在 AND/OR 树上做精确动态规划，递推式为
    \[
    \mathrm{OPT}(T') = \min_{f_i \in \text{leaves}(T')} \left[ c_i + \hat s_i \cdot \mathrm{OPT}(T'|_{f_i=\top}) + (1-\hat s_i)\cdot \mathrm{OPT}(T'|_{f_i=\bot}) \right]
    \]
    复杂度 \(O(n\cdot 3^n)\)，\(n=10\) 时约 590K 次运算、约 20ms（单核）。
  - 该理论推广了 Krishnamurthy–Boral–Zaniolo 关于异构代价排序的定理。
- Larch-A2C：用 Gated Graph Neural Network 编码表达式树，适用于谓词结果在行内相关时，比 Larch-Sel 更复杂。
- 在线更新：每次 LLM 结果为 BCE 梯度步，7–11ms 内完成，隐藏在下一个 LLM 调用往返中；存在一个步骤的陈旧性，但验证表明对 token 成本影响仅 ±0.6%。

#### 级联路由（GAMCAL）
- 目标：降低每个求值谓词委托给 oracle 的比例 \(p_{\text{deleg}}\)。
- 双阈值机制：代理得分 \(<\tau_{low}\) 拒绝，\(\ge \tau_{high}\) 接受，中间区间委托给 oracle。
- 校准器：单调广义可加模型（GAM），在 log-odds 空间用惩罚极大似然拟合，并带平滑惩罚和单调性约束。
- 阈值求解：最小化成本–质量目标
  \[
  \min_{\tau_{low}\le\tau_{high}} \alpha\cdot\frac{1-E[F_1]}{1-E[F_1(0.5,0.5)]} + (1-\alpha)\cdot \text{deleg}(\tau_{low},\tau_{high})
  \]
- 随机校准得分：\(\tilde g_i = \sigma\left(f(s_i) + \Phi^{-1}(q_i)\cdot \text{se}(s_i)\right)\)，其中 \(q_i\sim U(0,1)\) 固定每次采样，使校准差区域的行更易进入不确定区间，实现隐式探索。
- 更新节奏：加倍调度（doubling schedule），每批从不确定区采样 \(\rho|B_t|\) 行加入标签缓冲，首次重拟合需两类标签均至少 \(n_{\min}\) 条；每查询重拟合事件数 \(O(\log n)\)。该流水线与过滤排序组件有交互（见下文组合分析）。

#### 组合理论
- **顺序组合规则（Hoare 风格，带成本语义）**：
  \[
  \frac{\langle D_0,S_1,D_1\rangle_{c_1(D_0)}\quad \langle D_1,S_2,D_2\rangle_{c_2(D_1)}}{\langle D_0, S_1;S_2, D_2\rangle_{c_1(D_0)+\phi_1(D_0)\cdot c_2(D_1)}}
  \]
  其中 \(\phi_1(D_0)\) 是上游的扇出（每输入输出项数）。
- **条件成本分解**：对合取过滤负载，总成本为
  \[
  \text{Cost} = N \cdot \bar e \cdot \left(c_{\text{proxy}} + p_{\text{deleg}}\cdot c_{\text{oracle}}\right)
  \]
  假设：调用成本均匀、谓词选择性行内独立、基于缓存未命中条件化。

  - Larch 降低 \(\bar e\)（从 \(m\) 降至约 1.25）；
  - GAMCAL 降低 \(p_{\text{deleg}}\)（从 1 降至约 0.30）；
  - 在独立性下两个缩减相乘，得到 11.4× 上界。

- **三类跨组件交互（降低上界）**：
  - \(\kappa_1\)：级联边界的自选择——只有通过前序谓词的行才到后续级联，这些行偏向困难样本，使实际委托率高于全局率，对 \(p_{\text{deleg}}\) 乘性惩罚 \([1.0,1.5]\)；
  - \(\kappa_2\)：样本预算收缩——短路减少后级联每批可得 oracle 标签减少，早期收敛变慢，对早期 \(p_{\text{deleg}}\) 惩罚 \([1.0,1.3]\)，长查询中平均影响小；
  - \(\kappa_3\)：选择性估计漂移——级联在 accept/reject 区域返回代理决策而非纯 oracle 标签，使 Larch 梯度变噪，对 \(\bar e\) 惩罚 \([1.0,1.4]\)。

  - 最终现实约 8×（中点 \(\kappa_1=1.25,\kappa_3=1.2\) 时约 7.8×；悲观 5.7×；乐观恢复 11.4×）。

## 6. 主要结论与发现

- **LLM 延迟窗口使在线学习成为可行成本优化手段**：每个 LLM 调用往返足以隐藏 CPU 端训练，使每调用梯度更新和每批阈值求解成为现实。
- **组合式在线学习可分解成本因子**：过滤排序降低 \(\bar e\)，级联路由降低 \(p_{\text{deleg}}\)，两者在独立条件下相乘，得到 11.4× 成本降低上界。
- **实际提升受三类跨组件交互制约**：自选择、样本预算收缩、选择性估计漂移，将上界降至约 8×；这些交互是结构性的但可被优化器级调控缓解。
- **响应缓存作为非学习基线**：精确记忆化可覆盖同一成本因子，但在分析中采用条件化处理（缓存未命中路径）。
- **Cortex AISQL 实例验证框架可行性**：两个学习组件分别以 per-call 和 per-batch 节奏运行，训练开销均被 LLM 往返隐藏，流水线陈旧性影响极小（约 ±0.6%）。
- **提出未来多个方向**：填充设计空间其余层（prompt 缓存、模型替代、提示结构、自适应批处理）、跨查询学习、联合控制器、统一质量契约。

## 7. 优点

- **问题切中实践痛点**：LLM 调用成本主导查询成本且延迟足够大，这一观察切中生产系统实际，具有明确现实意义。
- **框架清晰、层次化**：以“决策粒度 × 更新节奏”定义设计空间，有利于系统化分类和扩展。
- **组合理论初步建立**：将 Hoare 风格顺序组合规则引入 LLM 边界学习，给出带成本语义的组合规则，并明确前向/后向交互分类，具有理论启发价值。
- **具体组件设计扎实**：
  - Larch 选择性估计器+DP 求解器，理论上达到精确最优排序，且样本效率高；
  - GAMCAL 利用校准 GAM 替代经验阈值统计，泛化能力强，在多数基准上显著减少委托率。
- **对现实复杂性的客观认识**：主动刻画三类跨组件交互，将乐观上界修正为现实估计，避免了过度宣称。
- **生产部署背书**：Cortex AISQL 为生产系统，其实例具有实际可信度。
