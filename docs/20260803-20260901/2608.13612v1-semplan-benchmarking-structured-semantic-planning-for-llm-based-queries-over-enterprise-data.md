## 摘要
面向企业数据的自然语言接口必须将模糊的请求转化为受治理且可执行的行为，同时处理无效查询、策略失败、成本和非确定性。SemPlan基准通过一个确定性的合成双语基准来评估这一架构设计空间，该基准包含1,800个英语和巴西葡萄牙语案例；其中1,200个案例构成冻结的科学评估子集。在相同模型配置下比较了四种架构：直接SQL生成（A1）、受限工具智能体基线（A2）、结构化语义请求生成后接确定性规划与执行（A3），以及澄清/有状态语义规划变体（A4）。在4,800条主要记录中，答案正确率绝对水平较低：A1为22.25%，A2为22.58%，A3为25.67%，A4为24.25%。A3具有最高的观测正确率，并在预先指定的配对正确性分析中显著优于A1、A2和A4，而A1保持了最高的策略正确率和最低的不安全或无效率。A4具有最低的平均API成本和最低的虚假拒绝率。在预先选定的150案例稳定性子集上，答案正确的可重复性范围为92.00%至98.67%。结果支持权衡解释而非普遍排序：额外的结构约束改变了失败模式和效率，但并未单调地提升正确性，也没有解决歧义和多轮状态一致性问题。

## Abstract
Natural-language interfaces to enterprise data must translate underspecified requests into governed, executable behavior while controlling invalid queries, policy failures, cost, and nondeterminism. SemPlan Benchmark evaluates this architectural design space with a deterministic synthetic bilingual benchmark containing 1,800 cases in English and Brazilian Portuguese; 1,200 cases form the frozen scientific evaluation subset. Four architectures are compared under the same model configuration: direct SQL generation (A1), a bounded tool-agent baseline (A2), structured semantic-request generation followed by deterministic planning and execution (A3), and a clarification/stateful semantic-plan variant (A4). Across 4,800 primary records, answer correctness was low in absolute terms: 22.25% for A1, 22.58% for A2, 25.67% for A3, and 24.25% for A4. A3 had the highest observed correctness and significantly exceeded A1, A2, and A4 in the pre-specified paired correctness analysis, while A1 retained the highest policy-correct rate and the lowest unsafe-or-invalid rate. A4 had the lowest mean API cost and lowest false-refusal rate. On a preselected 150-case stability subset, answer-correct repeatability ranged from 92.00% to 98.67%. The results support a trade-off interpretation rather than a universal ranking: additional structural constraints changed failure modes and efficiency, but did not monotonically improve correctness or solve ambiguity and multi-turn state consistency.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：面向企业数据的自然语言接口面临着"语法正确但语义错误/策略违规/操作无效"的困境。企业分析问题常涉及业务指标、隐式维度、时间范围、授权边界、不受支持的操作和对话上下文，系统仅生成合法性 SQL 远远不够。
- **架构设计空间的根本疑问**：在 LLM 与确定性软件之间，不同的责任划分（直接生成SQL、选择工具、生成类型化语义表示、或与确定性归一化/执行层交互）如何影响系统的端到端正确性、策略行为、失败模式、成本与可重复性？
- **论文立场**：架构选择不仅是工程偏好，更对应关于"错误出现在哪一环、何种约束能提升可靠性"的不同实证假设。论文通过冻结模型、基准案例、数据库快照和评估规则，系统比较此类权衡。
- **核心结论预告**：不存在"结构越强越好"的单调规律——额外结构约束改变失败模式，但未线性提升正确性。

## 2. 方法论

### 核心思想
论文提出 **SemPlan Benchmark**，这是一个确定性的合成双语基准，在**控制模型配置不变**的前提下，比较四种不同的"LLM与确定性软件责任分配架构"，并引入金标准语义计划做确定性执行，以区分模型质量失败与基础设施失败。

### 四种对比架构
- **A1（直接 SQL 生成）**：LLM 直接输出 SQL（以严格 JSON 包裹），经解析、AST 白名单、复杂度限制、只读授权、超时与行数限制后执行。模型从不获得金标准 SQL/计划/答案。
- **A2（受限工具智能体）**：LLM 只能调用有界集合的类型化工具（聚合、排名、期间对比、预算对比、合同状态等），参数须符合严格 schema 和标准目录标识，不能写任意 SQL。
- **A3（结构化语义请求 + 确定性规划/执行）**：LLM 生成严格语义请求信封（操作、指标、维度、过滤器、时间粒度、排序、限制、比较字段、澄清字段、置信度）。确定性归一化模块验证标识符与类型、解析语义规则、编译为可执行语义计划；**SQL 由应用程序生成，而非 LLM**。
- **A4（澄清 + 有状态语义规划）**：在 A3 基础上增加结构化状态、类型化澄清结果、PATCH/REPLACE 多轮更新语义；仅按兼容规则更新被 PATCH 显式更改的字段；执行保持确定性。

### 技术细节
- 金标准语义计划在参考数据库上确定性执行，产生归一化黄金答案。
- 基准构建区分文本案例与表格数据；用参数化模板定义意图、指标、维度、过滤器、时间上下文、歧义和策略期望；用多种子确定性随机数生成器保证可复现。
- 统计框架采用**配对设计**（同一案例在各架构下对齐比较），McNemar 检验 + 配对风险差 95% CI + Holm-Bonferroni 多重性校正；偏态连续变量（如成本）用配对 bootstrap 对比。

## 7. 优点

- **控制变量的架构对比设计**：在同一模型/提示词冻结/案例集配置下比较四种同类架构，避免跨模型混淆，科学严谨。
- **预注册式研究设计**：冻结研究问题、方向性假设、主要分析方案后才执行隐藏评估，结果保留混合/负面发现，不定义后验假设。
- **多维评估体系**：不止看正确率，还系统测量策略正确性、假拒绝、不安全/无效率、成本、可重复性、歧义澄清、多轮状态一致性，给出"权衡视图"而非单指标排序。
- **细粒度失败分类**：区分执行失败、输出契约无效、策略违规、目录未知标识符、配置无效，支持"失败转移"解读而非简单"更好/更差"。
- **可复现性工程化**：冻结提示词哈希、原始响应哈希、清单、成本账本、无密钥可复现路径，构建完整重放链。
- **诚实的方法论反思**：明确披露单作者金标准审核的偏差限制、延迟指标被排除的原因、外部有效性边界。

## 8. 不足与局限

- **绝对正确率过低**：最佳架构（A3）的答案正确率仅 25.67%，远达不到部署可用水平；作者明言基准偏难，不代表生产就绪。
- **单一合成领域**：仅 Northstar Commerce 分析域，概括到其他 schema/组织/数据分布未知。
- **单一模型与供应商**：仅测 gpt-5.6-luna，不涉及模型家族比较、微调或本地化部署。
- **语言覆盖有限**：仅英语和巴西葡萄牙语，且所有架构在葡语上明显更差，尚未探究原因。
- **金标准人工审核偏差**：全部 3,600 条审核记录来自单一人类评审者（即作者本人），作者-in-the-loop 偏差风险无法完全消除。
- **延迟指标失效**：由于捕获的类型化失败记录零延迟且分布不均，端到端延迟被排除在主结论之外。
- **多轮与歧义性能极弱**：多轮序列状态正确率仅 14%-20%，澄清决策正确率最高仅 27.38%，说明状态与澄清机制远未成熟。
- **统计与设计限制**：子组样本量有限，模板族可能相关，语言/难度/类别的探索性分析不应提升为主假设；架构间提示词与实现细节的差异无法完全排除。
- **架构空间未穷尽**：混合系统（A3 式语义请求 + 更强策略执行/替代状态模型）值得作为新预注册实验验证，而不能事后并入已完成运行。
