## 摘要
企业越来越多地希望通过AI驱动的工具（如语义运算符或深度研究代理）使用自然语言查询数据湖。然而，深度研究代理作为一个不透明的黑盒运作，隐藏其中间推理和数据检索步骤，并且无法提供管理API成本和执行延迟的控制手段。与此同时，前者的成本对于企业级数据湖而言可能高得令人望而却步。因此，使用这些系统的分析师缺乏干预幻觉前提、验证中间结果或修正系统轨迹的能力。我们提出了Carnot，一个用于AI驱动分析的交互相执行引擎。Carnot将自然语言请求编译为物理执行图，并通过交互式笔记本界面将其呈现出来。用户无需盲目等待最终输出，而是可以评审计划、逐步执行运算符、检查中间数据，或直接编辑底层代码或语义运算符指令。Carnot的查询优化器将根据用户提供的成本或延迟约束来优化查询。我们的演示将展示Carnot如何帮助用户在受真实企业用例启发的工作负载上实现高效且可验证的洞察。

## Abstract
Enterprises increasingly seek to query data lakes using natural language via AI-driven tools like semantic operators or deep research agents. However, the latter operates as an opaque black box, hiding its intermediate reasoning and data retrieval steps, and failing to expose controls for managing API costs and execution latency. Meanwhile, the former can be prohibitively expensive for enterprise-scale data lakes. Consequently, analysts using these systems lack the agency to intercept hallucinated premises, verify intermediate results, or correct the system's trajectory. We present Carnot, an interactive execution engine for AI-driven analytics. Carnot compiles natural language requests into physical execution graphs and surfaces them through an interactive notebook interface. Rather than waiting blindly for a final output, users can critique the plan, incrementally execute operators, inspect intermediate data, or directly edit the underlying code or semantic operator instructions. Carnot's query optimizer will optimize the query with respect to cost or latency constraints provided by the user. Our demo will showcase how Carnot helps users achieve efficient and verifiable insights on workloads motivated by real enterprise use cases.

## 1. 核心问题与整体含义

- **研究动机**：企业越来越依赖AI驱动的查询系统（如语义运算符和深度研究代理）从非结构化数据湖中提取洞察。但现有系统存在两类根本缺陷：
  - **深度研究代理（Deep Research agents）**：将自然语言查询映射为自主探索、写代码、解释执行结果的循环过程，但整体是**黑箱**，不暴露中间推理步骤和数据检索过程，用户无法管理API成本和执行延迟。
  - **语义查询引擎（Semantic query processing engines）**：执行SQL-like语义查询计划，但查询一旦提交，用户便无法在运行中检测错误算子、利用部分执行结果，或选择性地修补再执行流水线。
- **核心痛点**：用户（分析师）缺乏**可见性（visibility）**——无法在执行前、中、后检查每个提示词、代码块和中间结果；也缺乏**可操控性（steerability）**——无法在不丢弃已计算结果的情况下干预任意步骤。
- **整体意义**：Carnot试图在数据库查询计划的可优化结构与agent的迭代灵活性之间架设桥梁，将"人在回路"贯穿于每一步，弥补现有AI数据分析系统的关键缺失。

## 2. 方法论

- **核心思想**：将自然语言请求自动编译为**物理执行图（DAG of physical operators）**，并以**交互式笔记本**界面呈现，赋予用户全程检查与干预能力。
- **关键技术细节**：
  - **数据集抽象**：`Dataset`类是文件列表的包装器，暴露一组可链式操作的运算符，包括**语义运算符**（基于LLM的map、filter、join等）和**代理运算符**（数据探索、Python代码生成与执行、通用推理）。
  - **查询规划器（QueryPlanner）**：基于LLM agent，搭配few-shot演示来组合Carnot算子词汇中的执行计划。在调用昂贵LLM算子之前，会先通过**数据发现子代理（data discovery subagent）**对数据集进行采样、模式分析和结构总结。
  - **查询优化器（QueryOptimizer）**：受Abacus中Cascades风格优化器启发，共享类似的实现与变换规则，但最终由**LLM代理**从成本、延迟、质量的估计Pareto前沿中选择物理计划。
  - **交互式执行模型**：DAG经拓扑排序映射为笔记本单元格，每个单元格对应一个物理算子。用户可执行单个单元格、就地编辑（如修改语义过滤器的谓词）、保存后由优化器重新优化，并**重用未受影响上游单元格的缓存结果**。
  - **后端架构**：Postgres存储用户、数据集和workspace（会话-笔记本对）元数据；用户文件存入私有S3；存储与LLM抽象可切换为本地文件系统/本地模型以保障隐私。
  - **多层次检查**：每个单元格支持三种抽象层级查看——自然语言意图摘要、生成的代码/LLM提示词、原始输入输出数据对。

## 6. 主要结论与发现

- 现有AI数据查询系统在**透明性和可控性**上的缺失是真实且关键的痛点，Carnot通过**物化执行图为交互式笔记本**有效解决了这一问题。
- Carnot的核心发现是：将**数据库查询计划的可优化结构**与**agent的迭代灵活性**相结合，同时保持**人在回路**，能够在不牺牲自动化收益的前提下，让用户高效获得可验证的洞察。
- 用户的编辑和反馈可以被**在线整合到优化器**中，实现"边执行边修正"的闭环——上游计算结果可复用，避免重复计算成本。
- 成本/延迟约束可以被优化器显式处理，通过动态替换算子实现（如用更小更便宜的模型替代大模型执行低精度过滤），在预算内保持结果质量。

## 7. 优点

- **系统设计清晰**：前端（聊天+DAG+笔记本）与后端（Postgres+S3）分离，架构模块化，便于扩展和私有化部署。
- **人机协作粒度细**：提供从自然语言摘要到底层代码的**三级抽象**查看，满足不同技术水平的用户需求。
- **增量重执行机制**：用户编辑单元格后，只重算受影响算子并复用上游缓存，避免重复成本，这是交互体验的技术核心。
- **成本感知优化**：将LLM算子的实现选择形式化为Pareto前沿上的成本-延迟-质量多目标优化，实用性强。
- **延迟执行（deferred execution）**：在计划生成后、执行前暂停，让用户先审阅再消耗token，节省不必要的API费用。
- **演示场景设计贴切**：三个场景分别对应三类核心能力，逻辑完整且可操作性强。

## 8. 不足与局限

- **无正确性保证**：作者明确承认Carnot不提供计划准确性或正确性的保证。虽然可参考LOTUS的做法用oracle提供统计保证，但oracle本身也可能出错，属于"软保证"。
- **数据集规模有限**：演示数据集仅1,000条产品评论和KramaBench法律数据，未验证在更大规模、更复杂的企业数据湖上的扩展性。
- **缺乏定量用户研究**：未测量Carnot相比黑箱深度研究代理或传统语义系统的实际效率提升、用户信任度变化、任务完成时间等量化指标。
- **非线性DAG展示不足**：笔记本界面本质是线性排序的单元格，难以自然地展示计划DAG的非线性依赖关系，作者也将其列为未来工作。

- **评估客观性风险**：由于是自研系统演示，缺少第三方独立评估或与同类系统的横向对比，公正性有待进一步研究验证。
